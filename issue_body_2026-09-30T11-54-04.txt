This request uses the official issue template. It supersedes API-created issue #3209, which has not received the processing label and has not started. The approved grid and static-data configuration is unchanged.

Runtime compatibility correction after the first attempt: EXTPAR stopped at `Cannot read in namelist radtopo`. Its generated `INPUT_RADTOPO` contains `radius=40000.0`, while `radius` is declared INTEGER in EXTPAR v5.21. A minimal gfortran reproduction failed with IOSTAT=5010 for that file and passed when only the literal was changed to `40000`. Both domains now explicitly set `radtopo_radius: 40000` as a JSON integer. `lradtopo` remains false; domain geometry, resolution, and all dataset choices are unchanged.
